# 3D 레벨 장면 — 설계 문서

작성일 2026-08-18.

레벨 화면 배경을 실시간 3D(WebGL / three.js)로 바꾸고, 3매치 보드만 그 위에 2D 캔버스
오버레이로 얹는다. 기존 2D 상단 장면(`render/levelScene.ts` 계열)은 3D 가 대체한다.

## 왜

지금 상단 장면은 2D 캔버스에 그린 그림이다. 수심·포식자·잠수부가 전부 손으로 계산한
원근이라, 물의 부피감이 없고 안개가 진짜로 물체를 삼키지 않는다. 심해라는 소재는
**깊이 그 자체가 연출**인데 그걸 2D 로 흉내 내는 데 이미 3천 줄 가까이 쓰고 있다.
안개·조명·깊이 버퍼를 GPU 에 넘기면 같은 연출이 더 싸고 더 그럴듯해진다.

보드는 3D 로 만들지 않는다. 매치-3 는 **읽히는 게 전부**다. 원근이 들어가면 타일 색과
장애물 겹 수가 위치마다 다르게 보인다. 지금 2D 보드 렌더는 이미 충분히 좋고 검증돼 있다.

## 결정 요약

| 항목 | 결정 |
| --- | --- |
| 3D 범위 | 화면 전체 배경. 보드만 2D 오버레이 |
| 렌더러 | three.js (core 만, 동적 import) |
| 모델 조달 | 절차적 생성 위주. 잠수부만 기존 FBX → glb 변환 |
| 보드 정합 | 3D 해저에 보드 모양 구멍을 파고 2D 캔버스를 정확히 정렬 |
| 성능 기준 | 중급 폰 60fps 사수 |
| 유지할 연출 | 수심별 분위기(12m~640m), 포식자 3종 접근 위협 |
| 버리는 연출 | 장면 변형 4종(rescue/ice/rock/net), 보드 파편이 장면으로 날아가는 연속성 |

## 레이어 구조

```
.level-screen
 ├─ CSS 선형 그라디언트 배경        depthMood 의 top/bottom 색. 맨 뒤
 ├─ <canvas class="board-canvas">  2D. 배경 투명. 보드 사각형 안만 그린다. 입력을 받는다
 └─ <canvas class="stage3d">       three.js. 화면 전체. 맨 앞. pointer-events: none
```

**3D 가 위에 온다.** 반대로 놓으면 안 된다 — 보드 칸 배경은 모래 텍스처에 그늘을 덮은
불투명 면이라 뒤에 있는 3D 가 아예 안 보인다. 그런데 탈출 연출에서 **잠수부는 보드
물길 위를 헤엄쳐 지나가야 한다**(`descentPoint()`). 잠수부만 앞으로 빼는 방법도 있지만
레이어를 한 번 뒤집는 게 훨씬 싸다.

그 대가로 규칙이 하나 생긴다: **3D 오브젝트는 보드 사각형의 화면 영역을 침범하지 않는다.**
카메라가 고정이라 배치 단계에서 지키면 된다. 잠수부만 예외로, 탈출 중에만 들어온다.

3D 는 `pointer-events: none` 이라 히트테스트 경로는 지금과 같다.

배경 그라디언트를 3D 안의 메시가 아니라 CSS 로 두는 이유도 이것이다. 3D 가 맨 앞이라
배경 메시를 두면 그게 보드를 덮는다. `renderer` 는 `alpha: true` 로 투명하게 지우고,
`FogExp2` 색만 CSS 그라디언트의 아래쪽 색과 맞춘다.

### 좌표 주도권은 2D 가 쥔다

`BoardView` 가 지금처럼 보드 사각형을 계산하고, 그 값을 `stage.setBoardRect(x, y, w, h)`
로 3D 에 통보한다. 반대로 3D 가 정하면 입력 좌표계가 GPU 쪽 계산에 끌려간다.

3D 카메라는 원근(perspective) 고정 정면. 해저 바닥면을 `z = 0` 평면에 놓는다. 보드
화면 사각형을 그 평면으로 언프로젝트하면 구멍의 월드 좌표가 정확히 떨어진다.
매 프레임이 아니라 **리사이즈 때만** 계산한다.

정합이 어긋나면 즉시 티가 나므로 다음 경우를 전부 확인한다: 회전, 노치 기기의
safe-area, 모바일 주소창 접힘/펼침, `ResizeObserver` 발화.

### 장면 높이 개념이 사라진다

지금은 `BoardView` 가 캔버스 위쪽 높이(`sceneH`)를 `ScenePainter` 에게 떼어주고 아래를
보드로 썼다. 3D 가 화면 전체를 덮으므로 그 분할이 필요 없다. 보드는 아래쪽에 정렬하고
위 여백은 그냥 물속이다.

## 3D 씬 구성

성능 예산: **드로우콜 30 이하, 삼각형 40k 이하, 그림자 없음, 포스트프로세싱 없음.**

| 요소 | 구현 | 드로우콜 |
| --- | --- | --- |
| 자갈 해저 | `InstancedMesh` 자갈 1종 × 수백 개. 보드 구멍은 인스턴스 배치에서 제외 | 1 |
| 바위·해조 | 저폴리 절차 지오메트리(구·실린더에 노이즈 변형). 시드로 배치 | 3~5 |
| 물빛·수심 | `FogExp2`. `depthMood(t)` 의 색·밀도를 그대로 먹인다 | 0 |
| 수면 광선 | 가산합성 빌보드 몇 장 + 노이즈 UV 스크롤 | 2 |
| 코스틱 | 바닥 머티리얼에 `onBeforeCompile` 셰이더 패치(두 겹 노이즈) | 0 |
| 마린 스노우·기포 | `Points` 1개. 셰이더로 흐름 | 1 |
| 잠수부 | glb 1개 | 1~2 |
| 포식자 | 절차 메시. 한 번에 하나만 씬에 존재 | 2~3 |
| 조명 | directional 1 + hemisphere 1 | — |

- 3D 캔버스는 `devicePixelRatio` **1.5 상한**, 2D 보드 캔버스는 2 유지. 타일 선명도가
  곧 가독성이라 보드는 안 깎는다. 3D 는 안개에 잠겨 있어 1.5 로 떨어져도 안 보인다.
- 프레임 예산을 넘기면 **부유물 수 → 광선 수 → dpr 1.25** 순으로 자동으로 깎는다.

### 수심 (`render/depth.ts` 재사용)

`depthMood(t)` 는 그대로 둔다. 출력 소비처만 2D 페인트에서 3D 파라미터로 바꾼다.

| depthMood 출력 | 3D 매핑 |
| --- | --- |
| 물빛 | `FogExp2.color`, 배경 클리어 색, hemisphere 라이트 하늘색 |
| 광선 세기 | 광선 빌보드 개수와 불투명도 (0 이면 아예 씬에서 뺀다) |
| 마린 스노우 | `Points` 밀도와 크기 |
| 발광 | 가산합성 점광 스프라이트 개수 |

지도에 적힌 12m~640m 와 화면이 같은 값을 본다는 성질은 그대로 유지된다.

### 포식자 3종

접근 계산은 기존 `levels.ts` 의 `PREDATORS` 표와 곡선 로직을 그대로 재사용한다.
바뀌는 것은 그 값을 먹는 쪽뿐이다. 한 번에 하나만 씬에 있다.

- **곰치** — `TubeGeometry` + CatmullRom 곡선. 바위굴에서 뻗어 나온 곡선 길이가 남은 산소.
- **아귀** — 저폴리 몸통 + 가산합성 유인등. 안개 밀도 때문에 가까워져야 몸이 드러난다.
  2D 에서 손으로 맞추던 연출을 안개가 공짜로 해준다.
- **대왕오징어 촉수** — 튜브 하나가 위에서 내려온다. 몸통은 끝내 안 만든다.

2D 에서 쓰던 트릭 하나가 없어진다: `danger > 0.82` 일 때 아래턱만 잠수부 위에 한 번 더
그리던 것. 3D 는 깊이 버퍼가 알아서 하므로, 접근 곡선의 z 를 잠수부보다 카메라 쪽으로
잡기만 하면 잠수부가 위턱과 아래턱 사이에 놓인다.

### 잠수부

`tools/bake-diver-glb.mjs` 가 기존 `tools/lib/fbx.mjs` 파서를 재사용해
`assets-raw/quaternius-men/` 의 FBX 를 `.glb` 한 개로 굽는다. **런타임에 FBX 로더를
넣지 않는다** — 로더가 three 본체만큼 크다.

굽는 단계에서 지금과 같이 처리한다: Z-up 보정, -Y 정면 보정, 어깨 축으로 팔 75° 내리기,
옷 다시 칠하기(구리 헬멧 · 네오프렌 몸통 · 납 부츠). 색은 버텍스 컬러로 굽는다 —
텍스처를 안 쓰면 이미지 파일이 0개다.

동작은 관절이 아니라 몸 전체가 만든다. 주기가 어긋난 사인 둘을 겹쳐 천천히 오르내리며
좌우로 기운다. 위급하면 속도와 폭만 커진다. `render/diverRig.ts` 의 그 규칙을 그대로
3D 트랜스폼에 옮긴다.

## 파일

새로 만든다:

```
game/src/render3d/
  stage.ts        renderer·scene·camera·RAF·리사이즈·품질 티어·setBoardRect()
  seafloor.ts     자갈 InstancedMesh + 보드 구멍 + 바위·해조 배치
  waterVolume.ts  FogExp2 · 광선 빌보드 · 코스틱 셰이더 패치 (기존 render/water.ts 와 이름이 겹치지 않게)
  diver.ts        glb 로드 + 부유/위급 동작
  predators.ts    eel · angler · tentacle 절차 메시 + 접근 곡선
  particles.ts    마린 스노우 · 기포 Points
tools/bake-diver-glb.mjs
```

`stage.ts` 하나가 three 를 직접 만지는 유일한 파일이 아니다 — 각 파일이 자기 오브젝트를
만들어 `stage` 에 붙인다. 대신 **렌더 루프와 리소스 해제는 `stage.ts` 만 한다.**
각자 `dispose()` 를 노출하고 `stage.dispose()` 가 순서대로 부른다.

지운다: `render/levelScene.ts`(1451줄) · `render/gravel.ts` · `render/diverRig.ts` ·
`render/eelRig.ts` · `render/predatorRig.ts` · `ScenePainter` 인터페이스.

`sceneVariantFor()` 와 `SceneVariant` 타입은 **남긴다.** 3D 소품은 안 만들지만 지도 화면이
레벨 배지로 쓰고 있고(`screens/map.ts`) 테스트도 검사한다. 타입 선언만 `levelScene.ts` 에서
`levels.ts` 로 옮긴다 — 안 옮기면 지우는 파일에 타입이 남아 import 가 끊긴다.
`PredatorKind` 도 같은 이유로 `levels.ts` 로 옮긴다.

남긴다: `render/depth.ts`(3D 파라미터 소스) · `render/water.ts`(보드 칸 안의 물길 —
게임플레이 표시라 2D 유지) · `render/boardView.ts` · `tiles.ts` · `textures.ts`.

## 통합 지점

세 곳뿐이다.

1. **`game/src/screens/level.ts`** — `new LevelScene(...)` 를 `new Stage3D(...)` 로 바꾸고,
   `screen:destroy` 훅에서 `stage.dispose()` 를 부른다. 지오메트리·머티리얼·텍스처·
   WebGL 컨텍스트를 해제하지 않으면 레벨을 오갈수록 GPU 메모리가 샌다.
2. **`game/src/render/boardView.ts`** — `ScenePainter` 인터페이스와 `sceneH` 제거,
   `gravel` 제거, 캔버스 배경 투명, `resize()` 끝에서 `stage.setBoardRect(...)` 통보.
3. **`game/src/style.css`** — 캔버스 두 장을 겹치는 레이어. 3D 는 `pointer-events: none`.

## 번들과 로딩

three 는 `three/webgpu` 가 아니라 core 만 import 한다. tree-shake 후 gzip 약 150KB 예상.
`dist` 는 1.5MB 에서 약 2MB 가 된다.

지도·수족관 화면은 3D 를 안 쓴다. **레벨 진입 시점에 동적 import** 하고, 로드가 끝나기
전까지는 폴백 배경(아래)을 깔아 둔다. 첫 레벨 진입에서 한 프레임 정도 지연이 보일 수 있다.

## 폴백

2D 장면을 지우므로 3D 가 안 뜨면 화면이 빈다. 게임이 죽으면 안 되므로 최소 폴백을 둔다.

WebGL 컨텍스트 생성 실패, 또는 three 동적 import 실패 시:
`depthMood(t)` 색으로 만든 **CSS 선형 그라디언트**를 배경에 깔고 보드는 정상 작동시킨다.
잠수부도 포식자도 없다 — 산소 게이지가 압박을 대신한다. 코드는 20줄 정도.

이건 저사양 대응이 아니라 **사고 대응**이다. 저사양은 품질 티어가 처리한다.

## 테스트

- `core.test.ts` 46개는 DOM 무관이라 안 깨진다. `sceneVariantFor()` 검사 항목도 그대로
  둔다 — 함수를 남기기 때문이다.
- `npm run typecheck` 통과.
- 3D 는 유닛테스트 대상이 아니다. 실제 렌더로 확인한다:
  세로/가로 회전, 노치 safe-area, 주소창 접힘, 레벨 30판 왕복 후 GPU 메모리 증가 없음,
  수심 12m·110m·330m·640m 네 지점의 분위기 차이, 포식자 3종 접근 끝까지.

## 위험

1. **절차적 자갈이 지금 구운 2D 자갈보다 못생길 수 있다.** 지금 자갈은 칸마다 34알,
   알마다 3층으로 그린 공들인 결과물이다. 3D 에서는 조명이 그 역할을 대신해야 한다.
   먼저 자갈 바닥만 붙여 보고 판단한다.
2. **보드 구멍 정합.** 어긋나면 즉시 티가 난다. 위의 리사이즈 케이스 전부 확인.
3. **로딩 지연.** 레벨 진입에 스피너 한 프레임이 생길 수 있다.
4. **3D 가 보드를 가리는 사고.** 레이어가 뒤집혀 있으므로 오브젝트 하나가 보드 위로
   삐져나오면 타일이 안 보인다. 배치할 때 보드 화면 영역을 피하는 규칙을 지켜야 한다.
