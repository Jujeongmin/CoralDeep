# Coral Deep — 심해 수족관

**▶ 지금 플레이: https://verse8.io/s5Y3V8G**

매치-3 퍼즐 + 수족관 복원 메타 + 구조 타임어택. Verse8(Agent8) 배포용 Vite 프로젝트.
모바일 웹뷰(Verse8 앱) 세로 화면 기준으로 만들었다.

- 레벨을 깨서 **불가사리** 를 모으고, 그걸로 버려진 해저 연구소를 수족관으로 복원한다.
- 일부 레벨은 **구조 미션** 이다. 잠수부가 바위 틈에 갇혀 있고, **산소가 떨어지기 전에** 탈출로를 뚫어야 한다.
- 하트(생명) · 진주(코인) · 부스터 경제가 있고, **보상형 광고 11개** 지면이 붙어 있다.
- UI 아이콘은 전부 자체 제작 SVG다 (이모지 미사용, 외부 에셋 의존 없음).

## 실행

```bash
npm install
```

```bash
npm run dev
```

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (http://localhost:5173) |
| `npm test` | 퍼즐 코어 + 3D 무대 순수 함수 단위 테스트 120개 (`node --test`) |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm run build` | 프로덕션 빌드 → `dist/` |
| `npm run preview` | 빌드 결과 미리보기 |
| `node tools/make-icons.mjs` | UI 아이콘 SVG 재생성 |
| `node tools/make-tiles.mjs` | 보드 타일·장애물 에셋 재생성 |
| `npm run bake:diver` | 잠수부 glb 굽기 (Quaternius FBX → 정점색 + 스켈레탈 애니메이션) |
| `npm run bake:predators` | 포식자 3종 glb 굽기 (poly.pizza glTF → 정점색 + 애니메이션) |

Verse8 배포는 `dist/` 를 그대로 올리면 된다. 서버(`@agent8/gameserver`)는 쓰지 않는다 — 저장은 전부 로컬이다.

## 퍼즐 규칙

| 매치 | 결과 |
| --- | --- |
| 가로 4연속 | 해류(가로) — 그 행 전체 제거 |
| 세로 4연속 | 해류(세로) — 그 열 전체 제거 |
| L / T 자 | 기뢰 — 3×3 폭발 |
| 5연속 | 심연의 진주 — 같은 색 전부 제거 |

콤보: 해류+해류 = 십자 / 기뢰+기뢰 = 5×5 / 해류+기뢰 = 3행 3열 / 진주+특수 = 그 색 전부를 특수로 바꿔 동시 발동 / 진주+진주 = 보드 전체.

장애물: **산호암**(인접 제거로만 파괴, 타일 자리를 차지) · **잔해**(인접 제거로 파괴, 부순 자리가 물길이 된다) · **어망**(제거 판정 한 번을 흡수하고 타일은 생존, 스왑 불가) · **결빙**(겹 수만큼 제거 판정을 흡수하고 타일은 생존, 스왑은 가능).

여러 겹짜리 장애물은 **완전히 부순 순간에만** 목표 카운트로 센다.

**인접 피해는 사라진 타일 하나당 1 씩** 들어간다. 한 판정에 한 번만 깎으면, 기뢰 한 방으로 2겹 잔해의 인접 타일을 몰살한 뒤 남은 겹을 때릴 타일이 세상에서 사라져 클리어 불가 상태가 된다 (리필이 없어서 그렇다). 폭발이 장애물 칸을 *직접* 덮은 경우만 한 판정 1회로 묶는다.

## 탈출 미션 — 30단계 전부

**타일을 파내서 물길을 내고, 그 물길로 잠수부를 탈출시키는** 게 모든 레벨의 목표다.

- **새 타일이 위에서 내려오지 않는다.** 중력도 리필도 없다.
- 타일을 지우면 그 칸에 **물이 찬다.** 지운 자리는 영구히 물길로 남는다.
- 물이 **잠수부(`S`)부터 탈출구(`E`)까지 이어지는 순간** 잠수부가 그 길로 헤엄쳐 나가고 끝난다.
- 산호암·잔해는 인접 제거로 부수면 역시 물이 찬다. 결빙·어망은 덮개를 다 벗긴 **뒤에** 타일을 지워야 물이 찬다 — 결빙 2겹이면 그 칸을 뚫는 데 매치 3번이 든다.
- **산소는 한 수마다 1씩** 줄어든다. 부스터는 수를 쓰지 않으므로 산소도 쓰지 않는다.
- 길을 내기 전에 산소가 0이 되면 **이동 수가 남아 있어도 즉시 실패**한다.
- 리필이 없으니 **아무 데나 터뜨리면 길을 못 낸 채 보드가 말라버린다.** 어디를 팔지가 곧 퍼즐이다.
  둘 수가 완전히 없어지면(`deadBoard`) 그대로 패배한다.

핵심 코드: `Cell.passage`, `findEscapePath()`(BFS), `EscapePhase`, 목표 타입 `escape`.
연쇄가 없다 — 아무것도 움직이지 않으므로 한 수에 제거는 한 번뿐이다
(특수 타일끼리의 연쇄 발동은 `detonate` 안에서 처리된다).

### 보드는 직사각형이 아니다

레퍼런스(로얄킹덤)의 핵심은 보드 자체가 아니라 **자갈 더미 속에 파인 불규칙한 구멍이 보드**라는 점이다.
그래서 `layout` 의 `'#'`(보드에 없는 칸)을 빈 배경으로 두지 않고 **자갈로 꽉 채운다.**
(자갈은 예전엔 2D 캔버스에 알알이 그렸지만 지금은 3D 무대의 `InstancedMesh` 다 — 렌더링
방식은 "3D 배경 · 자갈 해저" 절 참고. 여기서는 그 구멍의 **모양**을 정하는 보드 쪽 규칙이다.)

보드 형태는 7종을 쓴다: 계단 · L자 · 십자 · 모래시계 · 대각 띠 · 지그재그 · 방.
`S` 와 `E` 는 그 형태 안에서 **서로 가장 먼 두 칸**(BFS 지름)으로 자동으로 잡는다 —
손으로 찍으면 형태 밖에 놓여 섬이 되는 사고가 난다.

타일은 칸보다 살짝 크게(1.1배) 그려 서로 맞물리게 한다. 사이가 벌어지면 블록이 아니라 아이콘으로 보인다.

### 물 렌더링 (`render/water.ts`)

칸마다 파란 사각형을 칠하면 '물 타일'로 보이지 액체로 안 보인다. 그래서 격자를 버렸다.

1. 물이 찬 칸마다 원을 찍은 **마스크**를 만들고 `blur + contrast` 를 걸어
   경계가 서로 녹아붙은 매끈한 덩어리(**메타볼**)로 만든다
2. 그 마스크로 물빛 그라디언트 · **코스틱**(수면 굴절광) · 기포를 오려낸다
3. 마스크를 살짝 위로 겹쳐 **수면 하이라이트**를 남긴다 — 이게 있어야 고인 물로 보인다
4. 새로 열린 칸은 `fill 0 → 1` 로 서서히 차오르므로 물이 **흘러드는** 것처럼 보인다

마스크는 물이 늘어날 때만 다시 만들고, 코스틱·기포만 매 프레임 움직인다.

## 보드 에셋 (`tools/make-tiles.mjs` → `tiles.ts`)

캔버스에 도형을 직접 그리면 색을 아무리 잘 써도 '단색 도형'으로 보인다.
그래서 타일·바위·결빙·어망을 **SVG 필터로 입체감을 구운 에셋**으로 만든다.

한 장에 들어가는 것:

| 요소 | 방법 |
| --- | --- |
| 바닥 그림자 | `feDropShadow` |
| 위쪽 베벨(빛 받는 면) | `feOffset` + `feGaussianBlur` + `feComposite out` → 흰색 |
| 아래쪽 그늘 | 같은 방식, 반대 방향 + 검정 |
| 바닥 반사광(림라이트) | 같은 방식, 아래쪽에 물빛 — **이게 있어야 물속에 뜬 입체로 보인다** |
| 유광 하이라이트 | 넓은 방사 그라디언트 + **작고 단단한 스페큘러 점** |
| 어두운 외곽선 | 물 위에서도 또렷하게 떨어져 보이게 |
| 표면 디테일 | 산호는 구멍, 해초는 잎맥, 조개는 방사 능선, 해파리는 속 비침, 진주는 무지갯빛, 바위는 결정·균열·붙어 자란 산호 |

SVG 필터를 매 프레임 적용하면 느리므로, **칸 크기가 정해질 때 한 번만 오프스크린 캔버스로 굽고**
그리기는 blit 만 한다 (`bakedTile`). 화면 크기가 바뀌면 `clearBaked()` 로 전부 버리고 다시 굽는다.

**상단 장면의 바위도 같은 파이프라인을 쓴다.** 조명 방향이 다르면 화면이 따로 놀기 때문이다.
`boulder-1..4` 네 변형을 시드로 골라 회전시켜 blit 한다 (`BOULDER_ART`).
다만 바위는 타일보다 **어둡고 무광**으로 구웠다 — 배경으로 물러나야 타일이 앞으로 나온다:

- 본체 색을 심해 암석 톤으로 (`#6b7b8b → #18202a` 계열)
- 위쪽 베벨 0.9 → 0.42, 림라이트 0.5 → 0.22
- 유광 하이라이트 없음 (바위가 젤리처럼 번들거리면 안 된다)
- 면 분할(`facets`)로 빛 받는 면과 그늘진 면을 나눠 덩어리감을 준다
- 일부에는 산호가 얹혀 있다

크기는 8px 단위로 묶어 캐시가 불어나지 않게 한다.

색이나 질감을 바꾸려면 `make-tiles.mjs` 만 고치고 다시 실행하면 된다. 게임 코드는 안 건드려도 된다.

### 난이도 곡선

| 구간 | 내용 | 산소 |
| --- | --- | --- |
| 1~5 | 7×7. 짧고 곧은 통로, 한 번 꺾임 | 12~17 |
| 6~10 | 8×8. 여러 번 꺾이는 길, 단단한 잔해(`X`) 등장 | 18~22 |
| 11~16 | 결빙·산호암·어망이 곁들여져 매치 위치가 제한됨 | 22~26 |
| 17~24 | 9×9. 길이 길고 굽이침, 색 수집 곁들임 | 26~30 |
| 25~30 | 지그재그 장거리 굴착, 단단한 잔해 다수 | 31~36 |

산소는 항상 이동 수보다 적다 (`oxygen < moves`) — 그래야 제한이 실제로 압박이 된다.

`core.test.ts` 가 30레벨 전부 자동 검사한다:
레이아웃 크기, S/E 개수, **잔해를 다 뚫으면 실제로 길이 이어지는지**(끊기면 클리어 불가 레벨),
**시작부터 이미 뚫려 있지는 않은지**, 난이도 단조성, 장면 변형 선택.

실패 사유가 시간이면 실패 모달이 이동 수 광고 대신 **시간 광고**(`oxygen-refill`)를 띄운다.
시간만 줘도 이동 수가 0이면 이어서 할 수 없으므로 이동 수도 같이 준다.
그림(`render/predatorArt.ts`)도 실제로 잡은 종을 그대로 띄운다 — 글은 "{predator}에게
잡혔어요"인데 그림이 다른 놈(또는 산소통)이면 왜 졌는지가 안 읽힌다.

**`oxygen` 값은 초가 아니라 눈금 수다** (눈금 하나 = `SEC_PER_UNIT` 2.5초).
화면에 내보낼 때는 반드시 곱해서 초로 바꾼다 — 안 그러면 "시간 +6"이라 써놓고
실제로는 15초를 주게 된다.

## 3D 배경 (`render3d/`)

**모든 레벨**의 보드 위·뒤에 실시간 three.js 배경이 붙는다. 로얄킹덤 스토어 스크린샷처럼,
숫자 게이지만으로는 안 생기는 압박과 생동감을 만드는 자리다. 자갈 해저·수면 광선·마린
스노우·잠수부·포식자로 이루어져 있고, 보드 자체는 여전히 2D 캔버스(`render/boardView.ts`)다.

**캔버스 두 장을 겹쳐 쓴다.** 3D 캔버스가 화면 전체를 덮고 보드 캔버스가 그 앞(위 레이어)에
얹힌다. 두 좌표계가 다르므로(3D 는 뷰포트 기준 원근 투영, 보드는 자기 캔버스 로컬 px) 그대로
두면 어긋난다 — `BoardRect`(뷰포트 좌표 + 칸 점유 마스크)를 매 프레임 3D 쪽에 넘겨, 자갈밭이
보드 모양대로 구멍을 뚫고 광선판이 보드가 없는 빈 띠에만 서도록 맞춘다(`types.ts`).

three 는 `render3d/index.ts` 의 `createStage()` 에서만 동적으로 불러온다 — 지도·수족관
화면은 3D 를 안 쓰므로 앱을 켜자마자 그 무게를 내려받을 이유가 없다(빌드에서 `stage-*.js`
청크로 분리된다). `webglAvailable()` 로 WebGL 컨텍스트를 못 따면 `null` 을 돌려주고, 그때는
CSS 그라디언트 배경만 남고 보드는 정상 동작한다 — 저사양 대응이 아니라 사고 대응이다.
저사양은 `Stage3D` 가 프레임 시간을 재서 자동으로 품질 티어(입자 밀도 · 광선판 해상도 ·
`devicePixelRatio` 상한)를 낮추는 쪽이 처리한다.

### 수심 연출 (`render/depth.ts`)

**단계마다 장면을 따로 그리지 않는다.** 수심 하나(`depthT()`, 0..1)를 입력으로 받아
물빛·광선·부유물·발광·포식자 종류를 연속으로 바꾼다(`depthMood()`). 30단계가 전부 다르게
보이면서도 레벨을 더 붙이면 그 수심에 맞는 분위기가 저절로 나온다. 지도에 적힌 12m~640m
와 화면이 같은 값을 보므로 숫자와 그림이 어긋나지 않는다.

수심대는 실제 바다의 층을 따랐다. 얕은 곳은 파랑이 살아 있고 수면 광선이 내리꽂힌다.
깊어질수록 색이 빠지고 광선이 사라지며, 대신 **부유물과 발광이 늘어난다** — 볼 게
줄어드는 만큼 남은 것이 도드라져야 한다. 텅 빈 검은 화면은 깊이가 아니라 로딩 실패로
읽힌다.

| 수심 | 물빛 | 광선 | 마린 스노우 | 발광 | 포식자 |
| --- | --- | --- | --- | --- | --- |
| 12m | 밝은 청록 | 강함 | 거의 없음 | 없음 | 아귀(Anglerfish) |
| ~46m | 짙은 청 | 약함 | 보통 | 약간 | 아귀(Anglerfish) |
| ~180m | 흐린 남 | 거의 없음 | 많음 | 보통 | 고블린상어(Goblin Shark) |
| 640m | 검정에 가까움 | 없음 | 눈발처럼 | 강함 | 대왕오징어(Squid) |

포식자 전환 경계(`predatorFor()`, `levels.ts`)는 depth 0.34 / 0.68 에 있다 — 위 표의
~46m / ~180m 이 그 경계다.

### 자갈 해저 (`render3d/seafloor.ts`)

레퍼런스의 핵심은 보드 자체가 아니라 **'자갈에 파인 불규칙한 구멍이 보드'** 라는 점이다.
자갈 하나를 `InstancedMesh` 로 수백 개 뿌려 드로우콜 하나로 해저를 채우고, 조명이 알알이
입체감을 만든다. 인스턴스만으로는 사이 틈으로 배경이 비치므로 뒤에 구멍만 뚫린 바닥판을
깐다 — 구멍 자리(=보드 칸)에는 자갈도 바닥판도 배치하지 않는다. 보드는 계단·L자·十자 같은
불규칙한 모양이라 바운딩 박스 전체를 뚫을 수 없고, 칸 단위 마스크 텍스처로 프래그먼트
셰이더에서 discard 해 실제 보드 모양대로만 뚫는다.

### 광선판 (`render3d/waterVolume.ts`) · 마린 스노우(`render3d/particles.ts`)

수면에서 내리꽂히는 빛기둥은 가산합성 판 여러 장을 세워 카메라가 그 사이를 보게 하는
방식이다 — 판이 겹치는 곳이 밝아져 빛이 물에 퍼진 것처럼 보인다. 프래그먼트 셰이더가
알파를 쐐기 모양(수면에서 넓고 밝고, 깊이로 갈수록 좁고 옅게)으로 셰이핑해 균일한 막대가
아니라 광선으로 읽히게 한다. 마린 스노우와 기포는 `Points` 하나 · 드로우콜 하나 — 위치를
CPU 가 아니라 셰이더가 시간으로 계산해 매 프레임 버퍼를 다시 올리지 않는다. 둘 다 보드
사각형 위로 흘러 지나가면 타일을 가리므로, 보드 영역을 NDC 유니폼으로 넘겨 그 안에 들어간
조각을 discard 한다.

### 잠수부 (`render3d/diver.ts` · `tools/bake-diver-glb.mjs`)

**Quaternius 의 SpaceSuit 모델(CC0, FBX)** 을 굽는다. 원본은 `assets-raw/quaternius-men/`
에 있다. 예전에는 이 모델을 소프트웨어 렌더러로 PNG 스프라이트 한 장에 구웠지만(옷을
런타임에서 사인파로 흔들기만 했다), 지금은 Quaternius 애니메이션 라이브러리의 Idle 클립을
실제 스켈레탈 애니메이션으로 구워 `diver.glb` 에 정점 위치 몇 프레임으로 담는다 — 런타임은
스키닝을 하지 않고 그 프레임 사이를 보간만 한다. 텍스처 대신 정점 컬러로 칠해 런타임 이미지
자산이 0개다.

몸 전체의 움직임(오르내림·기울기·요)은 관절이 아니라 사인파 두 개를 겹쳐 만든다 — 물에 뜬
사람은 팔다리를 휘젓는 게 아니라 천천히 오르내리며 좌우로 기운다. 저폴리 모델을 관절로
꺾으면 이음매가 벌어져 종이인형처럼 보이므로, 이 규칙은 2D 스프라이트 시절부터 그대로다.
그 위에 위 스켈레탈 애니메이션(가슴 호흡, 팔 흔들림)을 얹는다. 위급할수록 사인파의 속도·
폭이 커진다.

### 포식자 접근 (`render3d/predators.ts`)

셋의 생김새는 다르지만 **접근 계산은 하나를 공유한다.** danger(0..1)가 world 위치를
far(멀리) → near(가까이) 로 옮기는 동시에 스케일도 far 에서 8%까지 줄었다가 near 에서
100%로 돌아온다 — 순수 원근만으로 "멀리서 티끌, 가까이서 위협적"을 만들려면 카메라에서
아주 멀리 둬야 하는데, 그 거리는 안개(FogExp2)가 이미 다 삼킨다. danger 는 이동 수(구조
미션은 산소)에서 오고, 계단식으로 뛰지 않도록 target/current 로 나눠 매끄럽게 보간한다.

물린 순간(잠수부가 실제로 입 안에 들어가는 연출)은 3D 무대로 아직 옮겨지지 않았다 —
실패 시 화면이 흔들리다 바로 실패 모달이 뜬다(`screens/level.ts`).

### 실패 모달 그림 (`render/predatorArt.ts`)

실패 모달은 이 판을 쫓아오던 그 생물을 그대로 보여준다. 이미지 에셋이나 새 의존성 없이
순수 canvas 경로로 세 종을 직접 그린다 — 그라디언트 · 레이어드 패스(머리/턱을 따로 그려
얹는다) · 반점 무늬 · 눈 하이라이트로, 3D 모델의 실루엣과 색감을 canvas 도형으로 다시
잡았다. `predatorArt()` 가 실제로 잡은 종을 골라 그린다.

### 포식자 3D 모델 (`tools/bake-predators-glb.mjs` → `sprites3d/*.glb`)

3D 장면(`render3d/predators.ts`)의 포식자 셋도 손으로 만든 저폴리 도형이 아니라 실제
심해생물 모델이다. **Quaternius 의 저폴리 물고기(CC0, glTF)** 를 poly.pizza 에서 받아 굽는다.
원본은 `assets-raw/poly-pizza/`(라이선스는 그 폴더의 `License.txt`)에 있고, 굽는 도구가
`game/src/assets/sprites3d/{anglerfish,goblinShark,squid}.glb` 를 낸다.

| 역할 | 생물 |
| --- | --- |
| (예전 곰치) | **아귀(Anglerfish)** |
| (예전 아귀) | **고블린상어(Goblin Shark)** |
| (예전 촉수) | **대왕오징어(Squid)** |

원본 glTF 는 색을 정점이 아니라 **재질**(`baseColorFactor`, 오징어만 텍스처 아틀라스)로
칠한다. `glb.ts`(런타임 파서)는 정점 색만 읽으므로 굽는 시점에 눌러 담는다: 재질만
있는 프리미티브는 `baseColorFactor`(linear 색공간)를 sRGB 로 변환해 그 프리미티브의
모든 정점에 칠하고, 오징어는 유일한 색 소스가 512×512 텍스처(`Sushi_Atlas.png`, 여러
모델이 공유하는 아틀라스로 보인다)라 UV 로 쌍선형 샘플링해 정점마다 다르게 칠한다 —
런타임 이미지 자산은 여전히 0개다.

아귀·고블린상어는 스킨 애니메이션 6개(Attack/Death/Out_Of_Water/Swimming_Fast/
Swimming_Impulse/Swimming_Normal)를 갖고 있다. 그중 가장 길고 매끄러운 루프인
**Swimming_Normal**(56키프레임, 2.292초)을 골라, 잠수부(`bake-diver-glb.mjs`)와 같은
방식으로 스키닝을 오프라인에서 CPU 로 미리 계산해 정점 위치 몇 프레임을 구워 넣는다
— 런타임은 여전히 스키닝을 하지 않고 두 프레임 사이를 보간만 한다. 오징어는 스킨도
애니메이션도 없어 정지 메시만 굽고, 장면에서는 흔들림·회전으로 생기를 준다.

세 파일 합쳐 400KB 예산 안(실측 ~375KB)에서 굽는다 — 자세한 예산 계산은
`tools/bake-predators-glb.mjs` 상단 주석 참고.

## 아이콘 에셋

이모지를 쓰지 않는다. `tools/make-icons.mjs` 가 27개 SVG를 `game/src/assets/icons/` 에 생성하고,
`icons.ts` 가 이를 Vite 에셋으로 import 한다. 전부 4 KB 미만이라 빌드 시 data URI 로 인라인된다
(네트워크 요청 0회). 직접 그린 것이라 라이선스 표기 의무가 없다.

### 아이템 아이콘은 UI 기호가 아니다

부스터·재화는 **가지고 있는 물건**이다. 선 몇 개로 그린 기호를 쓰면 인벤토리가 아니라
버튼 라벨처럼 읽힌다. 그래서 타일·잠수부와 **같은 필터 스택**(`ITEM_FILTERS`)으로 굽는다:
그림자 → 위 베벨 → 아래 AO → 바닥 물빛 림. 조명 방향(왼쪽 위)이 한 화면 안에서 통일된다.

- 팔다리·통·자루처럼 원통인 것은 **가로 3단 그라디언트**(`tube`)로 칠한다.
  세로 그라디언트는 '위가 밝은 판때기'가 된다.
- 작살은 눕혀서 미늘을 크게 뽑았다 — 곧게 세우면 정지한 막대고, 미늘이 없으면 화살이다.
- 해류는 선 세 줄이 아니라 두께가 변하는 **리본**으로 채웠다.
- 시작 부스터 3종(`pre-*`)은 전부 **둥근 토큰 안에 그 특수 타일이 들어 있는** 형태로 통일했다 —
  인게임 부스터와 한눈에 구분된다.
- 기뢰의 뿔은 막대가 아니라 **원뿔**이어야 한다. 막대면 태양 아이콘이 된다.
- 보상 상자는 리본 두른 선물상자 대신 **바다에서 건진 보물궤**다.

색을 바꾸거나 아이콘을 추가하려면 `tools/make-icons.mjs` 를 고치고 다시 실행하면 된다.

기성 아이콘 팩으로 갈아끼우고 싶다면 (전부 상업적 사용 가능):

| 출처 | 라이선스 | 비고 |
| --- | --- | --- |
| [game-icons.net](https://game-icons.net) | CC BY 3.0 | 4000+ SVG. harpoon/diver/cage/oxygen-tank 등 이 게임에 맞는 게 다 있다. 표기 필요 |
| [Kenney](https://kenney.nl/assets) | CC0 | 게임 UI 팩. 표기 불필요 |

바꿀 때는 `game/src/assets/icons/` 의 파일만 교체하면 된다. `icons.ts` 의 이름 매핑은 그대로 쓰면 된다.

## 소리 (`audio.ts`)

배경음은 두 겹이다. **음악**은 앱에 매달려 지도·수족관·판 안 어디서든 끊기지 않고,
**물소리 앰비언트**는 판 안에서만 그 위에 겹친다 — 심해로 내려가 있는 동안만 물이 가까이
흐르는 셈이다. 둘 다 같은 `bgmBus` 를 타서 설정의 '배경음' 슬라이더 하나가 함께 조절한다.

| 소리 | 출처 | 라이선스 |
| --- | --- | --- |
| 음악 (`bgm.ogg`) | ["Underwater Theme II" — Cleyton Kauffman](https://opengameart.org/content/underwater-theme-ii) | CC0 — 표기 불필요 |
| 물소리·기포·으르렁 | Freesound (504641 · 852478 · 539823 · 171178) | CC0 |
| UI·매치 효과음 | [Kenney](https://kenney.nl/assets) | CC0 |

**음악은 ogg 로 둔다.** mp3 는 인코더가 앞뒤에 무음 패딩을 붙여서 그대로 `loop = true`
로 돌리면 한 바퀴마다 소리가 끊긴다 — 원작자도 "루프에는 mp3 말고 ogg/wav 를 써라"라고
적어 뒀다. 형식을 바꿀 일이 있으면 이 제약을 먼저 확인할 것. ogg 는 그 패딩이 없어
버퍼를 통째로 돌리면 그대로 이어진다.

## 룰렛 (`render` 아님 — `screens/wheelView.ts`)

예전에는 격자 8칸에 표시등이 순서대로 켜졌다 꺼졌다. 그건 룰렛이 아니라 **로딩 표시**로 보인다.
도박성 연출의 긴장은 전부 **관성**에서 나온다: 처음엔 눈으로 못 따라갈 만큼 빠르고,
끝에서 한 칸씩 아쉽게 느려지다 멈춘다.

- 회전은 **CSS `transform` 전이 하나**로만 한다. 매 프레임 JS 로 각도를 계산하면
  메인 스레드가 밀릴 때 툭툭 끊긴다. transform 전이는 컴포지터가 돌린다.
- 출발 각을 `transition: none` 으로 못 박고 **리플로우를 강제해 확정시킨 뒤** 목표 각을 넣는다.
  `requestAnimationFrame` 으로 미루면 **탭이 백그라운드일 때 콜백이 안 돌아
  원반은 멈춰 있는 채 보상만 지급된다.**
- 목표 각은 항상 현재보다 크게 잡는다 (최소 5바퀴). 뒤로 돌면 룰렛이 아니다.
- 칸을 지나는 순간은 `rAF` 로 **계산된 행렬을 읽어 역산**한다 — 애니메이션의 실제 상태를
  보는 것이라 이징 함수를 JS 로 다시 구현할 필요가 없다. 지날 때마다 딸깍 + 포인터 튕김.
- 원반은 SVG 한 장이다. 칸을 DOM 요소로 깔면 경계에 안티에일리어싱 틈이 생겨 바퀴가 갈라져 보인다.
  아이콘은 `<img>` 라 SVG 안에 못 넣으므로 위에 얹는다.
- 당첨 확대는 **한 겹 안쪽 요소**(`.wheel-item-in`)가 맡는다. 바깥 `.wheel-item` 의 transform 은
  칸 위치를 잡는 데 이미 쓰고 있어서, 거기에 걸면 아이콘이 원반 한가운데로 튄다.

## 일일 보상

칸 7개를 같은 크기로 늘어놓으면 "오늘 뭘 받는지"와 "언제가 대박인지"가 안 보인다. 셋을 구분한다:

| 상태 | 처리 |
| --- | --- |
| 지난 날 | 채도·불투명도를 낮춰 뒤로 물리고 체크 도장을 찍는다 (CSS 로 그린다 — 아이콘을 더 얹으면 칸이 시끄러워진다) |
| 오늘 | 초록 테두리 + 맥동하는 발광으로 앞으로 끌어낸다 |
| 7일차 | 아래 줄 전체를 차지하는 큰 궤짝 |

칸 안의 읽는 순서도 정해뒀다: **며칠째 → 주 보상 하나(크게) → 곁들이 보상(작게)**.
주 보상은 부스터 > 하트 > 진주 순으로 하나만 고른다. 셋을 같은 크기로 늘어놓으면
뭐가 주 보상인지 알 수 없다.

맨 위에는 **연속 출석 일수**를 숫자로 못 박는다 — 계속 오게 만드는 동력이 그것이다.

## 하트 — 풀은 5, 보유 상한은 아니다

`MAX_HEARTS`(5)는 **자연 회복이 멈추는 지점**이지 보유 상한이 아니다. 5/5 인 상태에서
일일 보상·광고·룰렛으로 하트를 받으면 6, 7 … 로 그대로 쌓인다. 잘라 버리면 가득 찬
사람에게는 그 보상들이 아무 일도 안 하는 버튼이 된다 — 토스트는 뜨는데 숫자는 그대로다.

넘겨 받은 하트에는 두 가지가 따라붙는다:

- **자연 회복으로는 5를 절대 못 넘는다** (`refreshHearts`). 넘긴 만큼은 받아야만 생긴다.
- **진주 풀 충전(`fillHearts`)은 넘겨 든 하트를 깎지 않는다** — `max(현재, 5)`.

화면은 상한을 넘으면 표기를 바꾼다: HUD 는 분모를 떼고 숫자만(`6/5` 는 고장으로 읽힌다),
하트 모달은 칸 수를 보유 수만큼 늘린다.

서버에도 같은 규칙이 있고(`server.js` 의 `grantHearts`), 손으로 고친 계정을 위한 절대
상한만 따로 둔다 — `HEART_HARD_CAP`(99).

### 광고 동작 규칙

- 보상형은 **사용자 클릭에서만** 호출한다 (자동 재생 없음).
- `status === 'rewarded'` 일 때만 보상을 준다. `dismissed`/`failed` 는 토스트만.
- **재고 없음(no fill)이면 광고를 다시 요청하지 않는다.** SDK 에는 미리 물어볼 수 있는
  준비 상태 API 가 없어서(`showRewarded` 하나뿐) 재고가 없다는 사실은 한 번 요청해 본
  뒤에야 안다 — 렌더러 텔레메트리 `ad_not_ready`, 또는 결과 봉투의
  `platform_error` + `no_fill`(`@verse8/ads` PROTOCOL.md). 둘 중 먼저 오는 쪽에서
  `adPolicy.ts` 의 백오프(5분)를 걸고, 그동안 **모든 지면**을 닫은 뒤 버튼과 토스트에
  안내 문구(`adNotReady`)를 띄운다. 재고는 계정·세션 단위로 비므로 지면만 바꿔 눌러도
  같은 답이 온다. `unsupported_env` 래치와 달리 시간이 지나면 저절로 풀린다 — 재고는
  채워지는 것이라 세션 내내 잠글 이유가 없다. 광고제거 구매자의 '받기'(`canClaim`)는
  광고를 안 트니 이 백오프에 안 걸린다.
- 개발 환경(`import.meta.env.DEV`)에서만 시뮬레이션 오버레이로 폴백한다.
  **프로덕션 번들에는 시뮬레이션 코드가 아예 포함되지 않는다** (빌드 후 `ad-overlay` 문자열 0개 확인됨).

서버 사이드 검증(`ads-verifier.verse8.io`)은 문서상 선택이고 현재 보상이 전부 클라이언트 재화라 붙이지 않았다.
고가 보상을 추가하면 `ads.ts` 의 `requestId` 를 그대로 넘겨 검증을 붙이면 된다.

## 저장 — 계정 단위

`storage.ts` 의 `StorageAdapter` 인터페이스 뒤에 localStorage 구현체가 있다.
키가 계정별로 갈린다: `coraldeep.save.<account>` (계정을 못 받으면 `coraldeep.save.guest`).

계정은 Verse8 플랫폼이 iframe URL 에 넣어주는 `?auth=` 토큰에서 `@verse8/platform` 으로 꺼낸다.

### 계정 스코프 항목 (전부 `SaveData` 안에 있다)

| 분류 | 필드 |
| --- | --- |
| 진행도 | `levelStars`, `highestUnlocked`, `tasksDone` |
| 재화 | `pearls`, `stars`, `piggy` |
| 생명 | `hearts`, `heartsAt`, `infiniteHeartsUntil` |
| 인벤토리 | `boosters` |
| 주기 보상 | `dailyClaimedDay`, `dailyStreak`, `wheelFreeDay` |
| 광고 제한 | `adCounters` |
| 사용자 | `settings`, `nickname`, `accountId` |

광고 일일 상한(`adCounters`)을 계정에 붙인 게 중요하다. 전역이나 세션에 두면 상한이 우회된다.

**진행도(`levelStars`·`highestUnlocked`)는 서버만 올린다 — `syncAccount` 는 아예 안 본다.**
예전에는 `min(서버, 클라이언트)` 를 취해 "재동기화로 별점 자칭"만 막았는데, 반대 방향이
열려 있었다: 저장이 비어 있는 기기(사파리 프라이빗 모드, iframe 저장소 분리,
localStorage 를 지운 뒤)가 한 번 동기화하는 것만으로 계정 진행도가 그 빈 값까지 깎였다.
클라이언트 쪽도 짝을 맞춘다 — **저장된 기록 없이 시작한 세션은 스냅샷을 올리지 않고
`getAccount` 로 받아만 온다**(`hasStoredSave()`). 진행도는 소비되는 재화가 아니라 쌓이기만
하는 기록이라 min 을 취할 이유가 애초에 없다.

`reportLevelClear` 는 **해금 지점을 앞선 보고도 받는다.** 거절하면 보고 한 번이
실패(오프라인·타임아웃)한 뒤로 그 다음 판이 전부 거절돼 서버 진행도가 영영 못 따라잡는다.
막아서 얻는 것도 거의 없다 — 재도전 보고는 어차피 매번 보상을 주므로(승패를 검증할 수
없다는 한계) 진주를 부풀리는 길은 그 관문과 무관하게 이미 열려 있었고, 그 관문이 실제로
막던 것은 정직한 플레이어의 진행도였다.

**되돌리면 이득이 되는 값은 되돌아가지 않게 막는다.** 오늘의 무료 스핀 기록
(`wheelFreeDay`)이 그렇다 — 클라이언트를 그대로 믿으면 빈 값을 한 번 보내는 것(또는
localStorage 를 지우는 것)만으로 무료 스핀이 되살아난다. 그래서 서버·클라이언트 양쪽 다
**늦은 날짜가 이긴다**(날짜 키가 `YYYY-MM-DD` 라 문자열 비교가 곧 날짜 비교다).
광고 카운터를 `max` 로 받는 것과 같은 이유다.

### 연결이 한 번 실패해도 그 세션을 포기하지 않는다

계정 저장이 실제로 깨지던 자리는 병합 규칙이 아니라 **연결**이었다.

- 부팅 연결은 `2s → 5s → 10s` 로 세 번 더 시도한다(`BOOT_RETRY_MS`). 예전에는 한 번
  실패하면 `initDone` 이 켜진 채 남아 그 세션 내내 오프라인이었다 — 회선이 느리거나
  서버가 콜드 스타트면 8초 타임아웃에 그냥 걸린다. TowerWar 가 같은 증상으로
  `connectWithRegistry`(`BOOT_RETRY_MS`)를 넣은 자리와 같다.
- `connect()` 는 **동시 호출을 하나로 합치고 성공한 연결을 버리지 않는다.** Verse8 은
  살아 있는 연결이 하나뿐이라 겹쳐 부르면 앞 소켓이 닫힌다 — 판을 깨는 순간
  `reportLevelClear` 와 `syncAccount` 가 거의 동시에 나가므로, 합치지 않으면 둘 다
  실패할 수 있었다.
- 못 올린 클리어는 **저장에 큐로 남는다**(`pendingClears`). 다음 부팅과 화면 복귀에서
  순서대로 다시 보내고, 하나라도 실패하면 거기서 멈춰 큐에 남긴다. 계정 값을 받아오기
  **전에** 큐부터 비운다 — 순서가 반대면 방금 올린 판이 빠진 값이 화면을 덮는다.
- 설정 화면에 **저장 상태 한 줄**이 있다(계정 연결 / 기기 저장 / 못 올린 판 수, 누르면
  재시도). 배포본에서 어느 쪽이 죽었는지 콘솔 없이 확인할 수 있어야 한다.

### guest → 계정 마이그레이션

로그인 전에 guest 로 플레이한 기록은 첫 로그인 때 계정 키로 옮긴다 (`migrateGuestSave`).
계정 저장이 이미 있으면 손대지 않는다 — 기존 계정 진행도가 우선이다.

### 서버 저장으로 옮기려면

localStorage 는 기기 단위라 기기를 바꾸면 진행도가 따라가지 않는다.
계정을 따라가게 하려면 `StorageAdapter` 를 하나 더 구현해 `setAdapter()` 로 갈아끼우면 된다
(Agent8 게임 서버의 `$global.getMyState()` / `updateMyState()` 가 그대로 대응된다).
게임 코드는 어댑터 종류를 알지 못하므로 이 파일 하나만 바꾸면 된다.
`SaveData.updatedAt` 이 있어 서버/로컬 병합 기준으로 쓸 수 있다.

## 언어 (`i18n.ts`)

한국어 · 영어 · 일본어 · 번체 중국어 넷. 설정에서 고르면 저장에 남는다(`settings.lang`).

사전은 **키 순서를 KO 와 똑같이** 유지한다. 빠진 키는 `t()` 가 한국어로 되돌려주므로
화면이 깨지지 않는데, 바로 그래서 **눈으로는 못 찾는다** — 영어 화면에 한국어가 한 줄
섞여 있어도 그냥 지나간다. `core.test.ts` 가 소스에서 키를 세어 세 가지를 고정한다:

- 네 사전의 키가 정확히 같은가 (누락도, 한쪽에만 있는 키도 실패)
- 번역문에 한글이 남아 있지 않은가 (일본어·번체는 한자를 쓰므로 이 검사에 안 걸린다)
- 치환 자리(`{n}`, `{t}`)가 원문과 같은가

언어 선택은 눌러서 돌리는 버튼이 아니라 **네 개를 늘어놓은 격자**다. 넷이면 원하는
언어까지 최대 세 번 눌러야 하고, 무엇이 있는지도 안 보인다. 좁은 화면(320px)에서
라벨이 잘리지 않게 2열로 접는다.

언어를 바꾼 뒤에는 이 모달만 다시 그려선 안 된다 — 지도·독·HUD 의 글자는 이미 그려져
있어서 그대로 남는다. 화면을 통째로 다시 그린 뒤 설정을 다시 연다.

## 모바일 대응

Verse8 은 모바일 앱(`io.verse8.mobile`) 웹뷰에서 게임을 띄운다. 세로 화면 기준으로 만들었다.

- `viewport-fit=cover` + `env(safe-area-inset-*)` — 노치·홈 인디케이터 회피 (가로 인셋 포함)
- `mobile-web-app-capable` / `apple-mobile-web-app-*` — 전체화면 실행
- `100dvh` (+ `100vh` 폴백), `position: fixed` body — 주소창 높이 변화·고무줄 스크롤 차단
- `touch-action: none` (보드) / `manipulation` (그 외) — 더블탭 확대, 스크롤 하이재킹 방지
- `-webkit-touch-callout: none`, `contextmenu` 차단 — 길게 눌러도 메뉴가 안 뜬다
- `PointerEvent` 미지원 구형 웹뷰용 `touchstart/touchend` 폴백
- 입력 시점에 캔버스 크기를 재확인 — `ResizeObserver` 가 밀려도 탭 좌표가 어긋나지 않는다
- iOS 오디오 — 세 가지를 같이 해야 실제로 소리가 난다 (`audio.ts`):
  `navigator.audioSession.type = 'playback'` (무음 스위치를 안 타게), 컨텍스트가
  `running` 이 아니면 깨우기 (Safari 의 비표준 `interrupted` 상태까지 잡는다),
  첫 제스처 리스너를 **떼지 않고** 계속 달아 두기 (앱을 벗어났다 오면 다시 재워지므로)
- 정지 화면에서는 캔버스를 다시 그리지 않는다 (배터리)
- devicePixelRatio 상한 2
- 가로 모드 / 360px 미만 좁은 화면 미디어 쿼리
- `navigator.vibrate` 미지원(iOS)은 조용히 무시
