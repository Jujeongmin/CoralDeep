# Coral Deep — 심해 수족관

매치-3 퍼즐 + 수족관 복원 메타 + 구조 타임어택. Verse8(Agent8) 배포용 Vite 프로젝트.
모바일 웹뷰(Verse8 앱) 세로 화면 기준으로 만들었다.

- 레벨을 깨서 **불가사리** 를 모으고, 그걸로 버려진 해저 연구소를 수족관으로 복원한다.
- 일부 레벨은 **구조 미션** 이다. 잠수부가 바위 틈에 갇혀 있고, **산소가 떨어지기 전에** 탈출로를 뚫어야 한다.
- 하트(생명) · 진주(코인) · 부스터 경제가 있고, **보상형 광고 12개 + 전면 광고 2개** 지면이 붙어 있다.
- UI 아이콘은 전부 자체 제작 SVG다 (이모지 미사용, 외부 에셋 의존 없음).

## 실행

```bash
npm install
```

```bash
npm run dev
```

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (http://localhost:5173) |
| `npm test` | 퍼즐 코어 단위 테스트 46개 (`node --test`) |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm run build` | 프로덕션 빌드 → `dist/` |
| `npm run preview` | 빌드 결과 미리보기 |
| `node tools/make-icons.mjs` | UI 아이콘 SVG 재생성 |
| `node tools/make-sprites.mjs` | 곰치·잠수 케이지 배경 스프라이트 재생성 |
| `node tools/bake-diver-3d.mjs` | 잠수부 스프라이트 굽기 (Quaternius FBX → PNG) |

## 퍼즐 규칙

| 매치 | 결과 |
| --- | --- |
| 가로 4연속 | 해류(가로) — 그 행 전체 제거 |
| 세로 4연속 | 해류(세로) — 그 열 전체 제거 |
| L / T 자 | 기뢰 — 3×3 폭발 |
| 5연속 | 심연의 진주 — 같은 색 전부 제거 |

콤보: 해류+해류 = 십자 / 기뢰+기뢰 = 5×5 / 해류+기뢰 = 3행 3열 / 진주+특수 = 그 색 전부를 특수로 바꿔 동시 발동 / 진주+진주 = 보드 전체.

장애물: **산호암**(인접 제거로만 파괴, 타일 자리를 차지) · **잔해**(인접 제거로 파괴, 부순 자리가 물길이 된다) · **어망**(제거 판정 한 번을 흡수하고 타일은 생존, 스왑 불가) · **결빙**(겹 수만큼 제거 판정을 흡수하고 타일은 생존, 스왑은 가능).

여러 겹짜리 장애물은 **완전히 부순 순간에만** 목표 카운트로 센다.

**인접 피해는 사라진 타일 하나당 1 씩** 들어간다. 한 판정에 한 번만 깎으면, 기뢰 한 방으로 2겹 잔해의 인접 타일을 몰살한 뒤 남은 겹을 때릴 타일이 세상에서 사라져 클리어 불가 상태가 된다 (리필이 없어서 그렇다). 폭발이 장애물 칸을 *직접* 덮은 경우만 한 판정 1회로 묶는다.

## 탈출 미션 — 30단계 전부

**타일을 파내서 물길을 내고, 그 물길로 잠수부를 탈출시키는** 게 모든 레벨의 목표다.

- **새 타일이 위에서 내려오지 않는다.** 중력도 리필도 없다.
- 타일을 지우면 그 칸에 **물이 찬다.** 지운 자리는 영구히 물길로 남는다.
- 물이 **잠수부(`S`)부터 탈출구(`E`)까지 이어지는 순간** 잠수부가 그 길로 헤엄쳐 나가고 끝난다.
- 산호암·잔해는 인접 제거로 부수면 역시 물이 찬다. 결빙·어망은 덮개를 다 벗긴 **뒤에** 타일을 지워야 물이 찬다 — 결빙 2겹이면 그 칸을 뚫는 데 매치 3번이 든다.
- **산소는 한 수마다 1씩** 줄어든다. 부스터는 수를 쓰지 않으므로 산소도 쓰지 않는다.
- 길을 내기 전에 산소가 0이 되면 **이동 수가 남아 있어도 즉시 실패**한다.
- 리필이 없으니 **아무 데나 터뜨리면 길을 못 낸 채 보드가 말라버린다.** 어디를 팔지가 곧 퍼즐이다.
  둘 수가 완전히 없어지면(`deadBoard`) 그대로 패배한다.

핵심 코드: `Cell.passage`, `findEscapePath()`(BFS), `EscapePhase`, 목표 타입 `escape`.
연쇄가 없다 — 아무것도 움직이지 않으므로 한 수에 제거는 한 번뿐이다
(특수 타일끼리의 연쇄 발동은 `detonate` 안에서 처리된다).

### 보드는 직사각형이 아니다 (`render/gravel.ts`)

레퍼런스(로얄킹덤)의 핵심은 보드 자체가 아니라 **자갈 더미 속에 파인 불규칙한 구멍이 보드**라는 점이다.
그래서 `layout` 의 `'#'`(보드에 없는 칸)을 빈 배경으로 두지 않고 **자갈로 꽉 채운다.**

- 칸마다 자갈 34알씩, 알마다 본체·빛 받는 위·아래 그늘 3층으로 그린다
- 보드 바깥으로 한 칸 넘치게 그려 가장자리가 잘린 느낌이 안 나게 한다
- 열린 칸과 맞닿은 변에 어두운 띠를 넣어 **구멍을 둘러싼 단면**처럼 보이게 한다
- 자갈은 움직이지 않으므로 오프스크린에 한 번만 굽고 그 뒤로는 blit 만 한다

보드 형태는 7종을 쓴다: 계단 · L자 · 십자 · 모래시계 · 대각 띠 · 지그재그 · 방.
`S` 와 `E` 는 그 형태 안에서 **서로 가장 먼 두 칸**(BFS 지름)으로 자동으로 잡는다 —
손으로 찍으면 형태 밖에 놓여 섬이 되는 사고가 난다.

타일은 칸보다 살짝 크게(1.1배) 그려 서로 맞물리게 한다. 사이가 벌어지면 블록이 아니라 아이콘으로 보인다.

### 물 렌더링 (`render/water.ts`)

칸마다 파란 사각형을 칠하면 '물 타일'로 보이지 액체로 안 보인다. 그래서 격자를 버렸다.

1. 물이 찬 칸마다 원을 찍은 **마스크**를 만들고 `blur + contrast` 를 걸어
   경계가 서로 녹아붙은 매끈한 덩어리(**메타볼**)로 만든다
2. 그 마스크로 물빛 그라디언트 · **코스틱**(수면 굴절광) · 기포를 오려낸다
3. 마스크를 살짝 위로 겹쳐 **수면 하이라이트**를 남긴다 — 이게 있어야 고인 물로 보인다
4. 새로 열린 칸은 `fill 0 → 1` 로 서서히 차오르므로 물이 **흘러드는** 것처럼 보인다

마스크는 물이 늘어날 때만 다시 만들고, 코스틱·기포만 매 프레임 움직인다.

## 보드 에셋 (`tools/make-tiles.mjs` → `tiles.ts`)

캔버스에 도형을 직접 그리면 색을 아무리 잘 써도 '단색 도형'으로 보인다.
그래서 타일·바위·결빙·어망을 **SVG 필터로 입체감을 구운 에셋**으로 만든다.

한 장에 들어가는 것:

| 요소 | 방법 |
| --- | --- |
| 바닥 그림자 | `feDropShadow` |
| 위쪽 베벨(빛 받는 면) | `feOffset` + `feGaussianBlur` + `feComposite out` → 흰색 |
| 아래쪽 그늘 | 같은 방식, 반대 방향 + 검정 |
| 바닥 반사광(림라이트) | 같은 방식, 아래쪽에 물빛 — **이게 있어야 물속에 뜬 입체로 보인다** |
| 유광 하이라이트 | 넓은 방사 그라디언트 + **작고 단단한 스페큘러 점** |
| 어두운 외곽선 | 물 위에서도 또렷하게 떨어져 보이게 |
| 표면 디테일 | 산호는 구멍, 해초는 잎맥, 조개는 방사 능선, 해파리는 속 비침, 진주는 무지갯빛, 바위는 결정·균열·붙어 자란 산호 |

SVG 필터를 매 프레임 적용하면 느리므로, **칸 크기가 정해질 때 한 번만 오프스크린 캔버스로 굽고**
그리기는 blit 만 한다 (`bakedTile`). 화면 크기가 바뀌면 `clearBaked()` 로 전부 버리고 다시 굽는다.

**상단 장면의 바위도 같은 파이프라인을 쓴다.** 조명 방향이 다르면 화면이 따로 놀기 때문이다.
`boulder-1..4` 네 변형을 시드로 골라 회전시켜 blit 한다 (`BOULDER_ART`).
다만 바위는 타일보다 **어둡고 무광**으로 구웠다 — 배경으로 물러나야 타일이 앞으로 나온다:

- 본체 색을 심해 암석 톤으로 (`#6b7b8b → #18202a` 계열)
- 위쪽 베벨 0.9 → 0.42, 림라이트 0.5 → 0.22
- 유광 하이라이트 없음 (바위가 젤리처럼 번들거리면 안 된다)
- 면 분할(`facets`)로 빛 받는 면과 그늘진 면을 나눠 덩어리감을 준다
- 일부에는 산호가 얹혀 있다

크기는 8px 단위로 묶어 캐시가 불어나지 않게 한다.

색이나 질감을 바꾸려면 `make-tiles.mjs` 만 고치고 다시 실행하면 된다. 게임 코드는 안 건드려도 된다.

### 물 텍스처를 실제 에셋으로 바꾸고 싶다면 (전부 CC0)

지금은 절차적으로 그려서 에셋이 0개다. 더 사실적인 물을 원하면:

| 출처 | 라이선스 | 쓸 것 |
| --- | --- | --- |
| [ambientCG](https://ambientcg.com/) | CC0 | Water 계열 노멀맵 · 코스틱 텍스처 |
| [Poly Haven](https://polyhaven.com/textures) | CC0 | 물/바닥 텍스처, HDRI |
| [Kenney](https://kenney.nl/assets) | CC0 | 2D 물 타일셋 |
| [OpenGameArt "caustics" 검색](https://opengameart.org/) | 항목마다 다름 — **CC0만 골라 쓸 것** | 코스틱 시퀀스 |

붙이는 자리는 `water.ts` 의 코스틱 그리는 블록 하나다. 거기서 선을 긋는 대신
불러온 텍스처를 `globalCompositeOperation='lighter'` 로 타일링하면 된다.

### 난이도 곡선

| 구간 | 내용 | 산소 |
| --- | --- | --- |
| 1~5 | 7×7. 짧고 곧은 통로, 한 번 꺾임 | 12~17 |
| 6~10 | 8×8. 여러 번 꺾이는 길, 단단한 잔해(`X`) 등장 | 18~22 |
| 11~16 | 결빙·산호암·어망이 곁들여져 매치 위치가 제한됨 | 22~26 |
| 17~24 | 9×9. 길이 길고 굽이침, 색 수집 곁들임 | 26~30 |
| 25~30 | 지그재그 장거리 굴착, 단단한 잔해 다수 | 31~36 |

산소는 항상 이동 수보다 적다 (`oxygen < moves`) — 그래야 제한이 실제로 압박이 된다.

`core.test.ts` 가 30레벨 전부 자동 검사한다:
레이아웃 크기, S/E 개수, **잔해를 다 뚫으면 실제로 길이 이어지는지**(끊기면 클리어 불가 레벨),
**시작부터 이미 뚫려 있지는 않은지**, 난이도 단조성, 장면 변형 선택.

실패 사유가 시간이면 실패 모달이 이동 수 광고 대신 **시간 광고**(`oxygen-refill`)를 띄운다.
시간만 줘도 이동 수가 0이면 이어서 할 수 없으므로 이동 수도 같이 준다.
그림도 곰치를 띄운다 — 글은 "곰치에게 잡혔어요"인데 그림이 산소통이면 왜 졌는지가 안 읽힌다.

**`oxygen` 값은 초가 아니라 눈금 수다** (눈금 하나 = `SEC_PER_UNIT` 2.5초).
화면에 내보낼 때는 반드시 곱해서 초로 바꾼다 — 안 그러면 "시간 +6"이라 써놓고
실제로는 15초를 주게 된다.

## 레벨 장면 (`render/levelScene.ts`)

**모든 레벨**의 보드 위에 잠수부가 나오는 장면이 붙는다. 로얄킹덤 스토어 스크린샷처럼,
숫자 게이지만으로는 안 생기는 압박과 생동감을 만드는 자리다.

**보드와 같은 캔버스를 나눠 쓴다.** 별도 요소로 두면 박스 두 개가 따로 노는 화면이 된다.
`BoardView` 가 캔버스 위쪽 높이를 `ScenePainter` 에게 떼어주고, 아래를 보드로 쓴다.
좌표계가 하나라서 **보드에서 터진 파편·기포가 경계 없이 장면까지 날아간다.**
보드는 장면 바로 밑에 붙여 그린다 — 사이에 빈 띠가 생기면 다시 따로 논다.

### 수심 연출 (`render/depth.ts` · `render/predatorRig.ts`)

**단계마다 장면을 따로 그리지 않는다.** 수심 하나(`depthT()`, 0..1)를 입력으로 받아
물빛·광선·부유물·포식자를 연속으로 바꾼다. 30단계가 전부 다르게 보이면서도 레벨을
더 붙이면 그 수심에 맞는 분위기가 저절로 나온다. 지도에 적힌 12m~640m 와 화면이
같은 값을 보므로 숫자와 그림이 어긋나지 않는다.

수심대는 실제 바다의 층을 따랐다. 얕은 곳은 파랑이 살아 있고 수면 광선이 내리꽂힌다.
깊어질수록 색이 빠지고 광선이 사라지며, 대신 **부유물과 발광이 늘어난다** — 볼 게
줄어드는 만큼 남은 것이 도드라져야 한다. 텅 빈 검은 화면은 깊이가 아니라 로딩 실패로
읽힌다.

| 수심 | 물빛 | 광선 | 마린 스노우 | 발광 | 포식자 |
| --- | --- | --- | --- | --- | --- |
| 12m | 밝은 청록 | 강함 | 거의 없음 | 없음 | 곰치 |
| ~110m | 짙은 청 | 약함 | 보통 | 약간 | 아귀 |
| ~330m | 흐린 남 | 거의 없음 | 많음 | 보통 | 대왕오징어 촉수 |
| 640m | 검정에 가까움 | 없음 | 눈발처럼 | 강함 | 대왕오징어 촉수 |

셋의 생김새와 등장 방향은 다르지만 **접근 계산은 하나를 공유한다** (`PREDATORS` 표).
등장 지점에서 잠수부까지 곡선을 따라 다가오고, 겨냥점은 입 오프셋만큼 뒤로 당긴다 —
회전축을 잠수부에 맞추면 입이 그를 지나쳐 가서 얼굴 옆을 스친 것처럼 보인다.

- **곰치** — 오른쪽 바위굴에서 몸을 뻗는다. 뻗어 나온 **길이**가 남은 시간이다.
- **아귀** — 열린 물에서 헤엄쳐 온다. 유인등이 먼저 보이고 몸은 물빛에 잠겨 있다가
  가까워져야 드러난다. **얼마나 보이는가**가 시간이다.
- **대왕오징어 촉수** — 위에서 팔 하나만 내려온다. 몸통을 끝내 안 보여주는 게 핵심이다.
  화면 밖에 얼마나 큰 게 있는지 모르는 편이 다 보여주는 것보다 무섭다.

곰치는 SVG 스프라이트를 쓰고 나머지 둘은 캔버스로 직접 그린다. 심해 생물은 실루엣과
발광이 전부라 도형 몇 개로 충분하고, SVG 를 더 굽는 것보다 가볍다.

**포식자는 두 번 그린다.** 배경 단계에서 전체를, 그리고 `danger > 0.82` 면 **앞쪽 조각만**
잠수부 위에 한 번 더. 잠수부는 배경보다 나중에 그려지므로 그대로 두면 코앞까지 왔을 때
사람이 턱 앞에 선 그림이 되어, 닿기 직전이라는 게 안 읽힌다. 아래턱(촉수는 가까운 갈고리)만
앞에 얹으면 위턱은 뒤에 남아 잠수부가 **사이에** 놓인다. 물린 순간만은 머리 전체를 덮는다 —
그 구도는 따로 맞춰놨고 조각만 얹으면 헐거워진다.

### 장면 변형 (목표에서 자동 선택 — `sceneVariantFor()`)

| 변형 | 조건 | 소품 |
| --- | --- | --- |
| `rescue` | 앞을 막은 장애물이 없는 레벨 | 잠수부를 가둔 바위 틈 |
| `ice` | 결빙이 제일 많은 레벨 | 빙벽이 녹아 내려간다 |
| `rock` | 산호암이 제일 많은 레벨 | 바위 벽이 위에서부터 한 덩어리씩 무너진다 |
| `net` | 어망이 제일 많은 레벨 | 그물 가닥이 하나씩 사라진다 |

소품은 **수심만큼 가라앉혀 그린다.** 다섯 함수가 각자 고정 팔레트를 쓰고 있어서, 그대로
얹으면 640m 의 검정에 가까운 물 위에 밝은 청록 빙벽이 혼자 형광등처럼 뜬다. 색을 일일이
고치는 대신 소품만 오프스크린에 그린 뒤 `source-atop` 으로 한 번에 물들인다 — 실제로
칠해진 픽셀만 물들고 빈 곳은 안 건드린다. 얕은 곳은 오프스크린을 아예 안 거친다.

소품은 **목표 달성률만큼 걷힌다.** 진행 상황이 화면으로 바로 보인다.

`rock` 변형은 판 하나를 슬라이드시키지 않는다. 서로 겹치게 쌓은 바위 12덩어리를 두고
**위에서부터 하나씩 부서져 사라지게** 한다 — "몇 개 부쉈는지"가 눈으로 세어진다.
덩어리마다 빛 받는 면·결·들쭉날쭉한 모서리를 따로 그리고, 일부에는 산호가 얹혀 있다.
뒤에는 어두운 덩어리를 깔아 사이로 배경이 비치지 않게 하고, 위에서는 잔돌이 흘러내리고,
남은 이동 수가 부족해지면 더미 전체가 자잘하게 흔들린다.
배치는 시드 기반이라 프레임마다 같다 (`hash01`).

### 제한 시간 = 다가오는 곰치

숫자 게이지가 아니라 **몬스터와 잠수부 사이의 간격**이 남은 시간이다.
(로얄킹덤의 "왕을 구하세요" 화면에서 뱀이 왕에게 다가오는 것과 같은 자리)

| `danger` | 곰치 |
| --- | --- |
| 0 | 화면 오른쪽 **밖**. 안 보인다 |
| 0.5 | 오른쪽 위에서 머리가 들어와 입을 벌린다 |
| 1 | 잠수부 코앞. 몸통이 화면을 가로지른다 |

모든 레벨에 나온다. 구조 미션은 남은 산소, 그 외 레벨은 **남은 이동 수**가 `danger` 다.

거리감을 만드는 건 세 가지가 같이 움직여야 한다:

- **굴 입구를 화면 밖(`w * 1.15`)에 둔다.** 가장자리에 두면 시작부터 머리가 화면 안에
  크게 들어와 "멀리 있다가 다가온다"가 아니라 "처음부터 코앞"이 된다.
  위로 빼지는 않는다 — 위에서 나오면 머리가 잘려 '무언가 초록색'으로만 보인다.
- **머리는 장면 높이의 28%.** 40% 였을 땐 굴 밖으로 조금만 나와도 화면을 채워
  다가올 거리 자체가 없었다. 몸통 굵기도 같은 이유로 줄였다.
- **잠수부도 작아야 한다** (장면 높이의 0.52 / 0.46). 사람이 절반을 넘게 차지하면
  곰치가 들어올 빈 공간이 남지 않는다.

중간 단계(0.5)가 화면에 보이는지가 핵심이다. 0 과 1 만 다르면 플레이어는 갑자기
나타났다고 느낀다 — **다가오는 걸 보여줘야** 시간이 줄고 있다는 게 읽힌다.

머리와 아래턱은 별도 스프라이트(`eel-head` / `eel-jaw`)라 경첩에서 실제로 턱이 열린다.
몸통은 굴 입구에서 머리까지 잇는 스플라인으로 그리고 S 자로 흔든다.

조립 규칙(경첩 위치, 벌릴 때 위턱이 같이 젖혀지는 0.5 : 0.16 비율)은 `render/eelRig.ts`
한 곳에만 있다. **실패 모달의 곰치 그림도 같은 함수로 그린다** — 아이콘을 따로 그리면
방금 쫓아오던 놈과 다르게 생겨서 "얘한테 잡혔구나"가 안 읽힌다.

### 다가오는 속도는 선형이 아니다

`reach = 0.18 + danger^1.7 × 0.74`

| `danger` | 선형이었을 때 | 지금 |
| --- | --- | --- |
| 0.5 | 0.55 | **0.41** |
| 0.8 | 0.77 | **0.69** |
| 1.0 | 0.92 | 0.92 |

일정한 속도로 다가오면 초반부터 계속 같은 압박이라 오히려 무뎌지고, 후반에 쫓기는
가속이 없다. 앞쪽을 늦추고 끝에서 확 덮치게 해야 시간이 줄고 있다는 게 몸으로 읽힌다.

### 물리는 순간 (`devour`)

잠수부가 **곰치 입 안에 들어가야** 한다. 그러려면 셋이 맞아야 한다.

- **겨냥점을 입 오프셋만큼 당긴다.** 머리 스프라이트의 회전축은 목덜미고 입은 거기서
  105 단위 앞이다. 목덜미를 잠수부에 맞추면 입은 그를 지나쳐 가서, 물린 게 아니라
  얼굴 옆을 스친 것처럼 보인다.
- **머리를 한 번 더 덮어 그린다** (`drawEelBite`). 곰치는 배경 단계에, 잠수부는 그 뒤에
  그려지므로 그대로 두면 잠수부가 턱 **앞**에 뜬다. 물린 순간만 머리를 위에 다시 그려
  위턱과 아래턱 사이에 끼운다. 물수록 턱이 닫힌다.
- **몸통의 S 자 흔들림을 입 좌표에도 반영한다.** 흔들림을 빼고 계산하면 턱 옆 허공에 물린다.

곰치와 잠수부가 서로를 기준으로 삼으면 순환이 되므로, `diverRest`(가만히 있을 때의 자리)를
따로 두고 둘 다 그걸 기준으로 계산한다.

연출은 1.1초이고 그 뒤에 실패 모달이 뜬다 (`level.ts`). 짧으므로 개발 중에는
`dev-rig.html` 의 `devour` 칸으로 확인하는 편이 빠르다.

### 모든 변형이 공유하는 것

- 부위별 스프라이트로 리깅된 잠수부 (아래 참고)
- 다가오는 곰치 (위 참고)
- `danger` 가 오르면 발버둥이 빨라지고, 얼굴이 패닉으로 바뀌고, 화면이 흔들리고, 붉은 비네트가 맥동한다
- 장애물을 하나 부술 때마다: 잠수부 만세 + 보드에서 기포가 솟아오름 + 화면 임팩트 흔들림
- 장면 바닥의 바위 턱 — 보드가 거기 얹힌 것처럼 이어붙인다

위협 강도와 소품 진행도는 목표값을 향해 보간되므로 수를 둘 때마다 툭 끊기지 않는다.

### 잠수부 스프라이트 (`tools/bake-diver-3d.mjs` → `sprites.ts`)

잠수부는 직접 그리지 않는다. **Quaternius 의 SpaceSuit 모델(CC0, FBX)** 을 굽는다.
원본은 `assets-raw/quaternius-men/` 에 있고, 굽는 도구가 `game/src/assets/sprites3d/` 에
PNG 한 장과 `diver.json`(기준점 · 전신 높이)을 낸다.

이 환경에는 Blender 가 없어서 **FBX 를 직접 읽는다** (`tools/lib/fbx.mjs`):
바이너리 파서 + z-버퍼 소프트웨어 렌더러 + 최소 PNG 인/디코더, 의존성 0개다.
메시 기하만 읽는다 — 재질·텍스처·스킨은 스프라이트로 굽는 데 필요 없고,
읽으려면 파서가 몇 배로 커진다.

**한 장으로 굽는다.** 예전에는 좌표를 보고 삼각형을 갈라 여섯 부위로 나눈 뒤 런타임에
관절마다 돌렸다. 저폴리 모델은 관절부가 실제로 이어져 있지 않아서, 꺾을수록 이음매가
벌어지고 종이인형처럼 보였다. 게다가 그 동작은 '살아 있음'보다 '덜컹거림'으로 읽혔다.

대신 **굽기 전에 3D 에서 팔을 내린다.** T 포즈라 팔이 X 축에 정렬돼 있어서, 어깨를 축으로
팔 정점만 75° 돌리면 자연스러운 자세가 된다. 포즈를 미리 고정하니 런타임에는 회전이 없고
이음매도 없다.

움직임은 관절이 아니라 **몸 전체**가 만든다 (`render/diverRig.ts`). 물에 뜬 사람은 팔다리를
휘젓는 게 아니라 천천히 오르내리며 좌우로 기운다. 주기가 어긋나는 사인 둘을 겹친다 —
하나만 쓰면 시계추처럼 규칙적이라 기계로 보인다. 위급하면 속도·폭만 커진다.

굽는 좌표계에서 두 번 틀렸으니 기록해둔다:

- FBX 표준은 Y-up 이지만 **Blender 로 내보낸 것은 Z-up** 이다. 틀리면 정수리에서
  내려다본 그림(팔이 좌우로 뻗은 T 자)이 나온다.
- Blender 인물은 보통 **-Y 를 향해** 서 있다. 그대로 보면 뒤통수만 나온다.

기준점과 전신 높이는 굽는 도구가 `diver.json` 으로 함께 내보낸다 — 손으로 옮겨 적으면
굽는 기준을 고칠 때마다 게임 쪽이 옛 비율로 남는다.

**옷은 다시 칠했다.** 원본은 흰 셔츠 + 청바지라 그대로 구우면 심해 잠수부로 안 읽힌다.
형태는 못 바꾸니 색으로 읽힌다: **구리 헬멧**이 정체를 한 번에 알리고, 네오프렌 몸통과
납 부츠가 그걸 받친다. 헬멧이 원래 불투명 판이라 얼굴이 없는데, 구리로 칠하면 그게
결함이 아니라 잠수 헬멧의 면갑으로 보인다 — 공포는 표정이 아니라 흔들림의 폭으로 전한다.

몸통을 더 어둡게 두면 640m 물빛에 실루엣이 잠긴다. 중간 톤을 유지하고 대비는 헬멧이
만들게 했다.

## 아이콘 에셋

이모지를 쓰지 않는다. `tools/make-icons.mjs` 가 27개 SVG를 `game/src/assets/icons/` 에 생성하고,
(곰치처럼 **게임 안에 이미 있는 것**은 아이콘을 새로 그리지 않고 그 스프라이트를 그대로 쓴다)
`icons.ts` 가 이를 Vite 에셋으로 import 한다. 전부 4 KB 미만이라 빌드 시 data URI 로 인라인된다
(네트워크 요청 0회). 직접 그린 것이라 라이선스 표기 의무가 없다.

### 아이템 아이콘은 UI 기호가 아니다

부스터·재화는 **가지고 있는 물건**이다. 선 몇 개로 그린 기호를 쓰면 인벤토리가 아니라
버튼 라벨처럼 읽힌다. 그래서 타일·잠수부와 **같은 필터 스택**(`ITEM_FILTERS`)으로 굽는다:
그림자 → 위 베벨 → 아래 AO → 바닥 물빛 림. 조명 방향(왼쪽 위)이 한 화면 안에서 통일된다.

- 팔다리·통·자루처럼 원통인 것은 **가로 3단 그라디언트**(`tube`)로 칠한다.
  세로 그라디언트는 '위가 밝은 판때기'가 된다.
- 작살은 눕혀서 미늘을 크게 뽑았다 — 곧게 세우면 정지한 막대고, 미늘이 없으면 화살이다.
- 해류는 선 세 줄이 아니라 두께가 변하는 **리본**으로 채웠다.
- 시작 부스터 3종(`pre-*`)은 전부 **둥근 토큰 안에 그 특수 타일이 들어 있는** 형태로 통일했다 —
  인게임 부스터와 한눈에 구분된다.
- 기뢰의 뿔은 막대가 아니라 **원뿔**이어야 한다. 막대면 태양 아이콘이 된다.
- 보상 상자는 리본 두른 선물상자 대신 **바다에서 건진 보물궤**다.

색을 바꾸거나 아이콘을 추가하려면 `tools/make-icons.mjs` 를 고치고 다시 실행하면 된다.

## 룰렛 (`render` 아님 — `screens/wheelView.ts`)

예전에는 격자 8칸에 표시등이 순서대로 켜졌다 꺼졌다. 그건 룰렛이 아니라 **로딩 표시**로 보인다.
도박성 연출의 긴장은 전부 **관성**에서 나온다: 처음엔 눈으로 못 따라갈 만큼 빠르고,
끝에서 한 칸씩 아쉽게 느려지다 멈춘다.

- 회전은 **CSS `transform` 전이 하나**로만 한다. 매 프레임 JS 로 각도를 계산하면
  메인 스레드가 밀릴 때 툭툭 끊긴다. transform 전이는 컴포지터가 돌린다.
- 출발 각을 `transition: none` 으로 못 박고 **리플로우를 강제해 확정시킨 뒤** 목표 각을 넣는다.
  `requestAnimationFrame` 으로 미루면 **탭이 백그라운드일 때 콜백이 안 돌아
  원반은 멈춰 있는 채 보상만 지급된다.**
- 목표 각은 항상 현재보다 크게 잡는다 (최소 5바퀴). 뒤로 돌면 룰렛이 아니다.
- 칸을 지나는 순간은 `rAF` 로 **계산된 행렬을 읽어 역산**한다 — 애니메이션의 실제 상태를
  보는 것이라 이징 함수를 JS 로 다시 구현할 필요가 없다. 지날 때마다 딸깍 + 포인터 튕김.
- 원반은 SVG 한 장이다. 칸을 DOM 요소로 깔면 경계에 안티에일리어싱 틈이 생겨 바퀴가 갈라져 보인다.
  아이콘은 `<img>` 라 SVG 안에 못 넣으므로 위에 얹는다.
- 당첨 확대는 **한 겹 안쪽 요소**(`.wheel-item-in`)가 맡는다. 바깥 `.wheel-item` 의 transform 은
  칸 위치를 잡는 데 이미 쓰고 있어서, 거기에 걸면 아이콘이 원반 한가운데로 튄다.

뭐가 주 보상인지 알 수 없다.

맨 위에는 **연속 출석 일수**를 숫자로 못 박는다 — 계속 오게 만드는 동력이 그것이다.

## 저장 — 계정 단위

`storage.ts` 의 `StorageAdapter` 인터페이스 뒤에 localStorage 구현체가 있다.
키가 계정별로 갈린다: `coraldeep.save.<account>` (계정을 못 받으면 `coraldeep.save.guest`).

계정은 Verse8 플랫폼이 iframe URL 에 넣어주는 `?auth=` 토큰에서 `@verse8/platform` 으로 꺼낸다.

### 계정 스코프 항목 (전부 `SaveData` 안에 있다)

| 분류 | 필드 |
| --- | --- |
| 진행도 | `levelStars`, `highestUnlocked`, `tasksDone` |
| 재화 | `pearls`, `stars`, `piggy` |
| 생명 | `hearts`, `heartsAt`, `infiniteHeartsUntil` |
| 인벤토리 | `boosters` |
| 주기 보상 | `dailyClaimedDay`, `dailyStreak`, `wheelFreeDay` |
| 광고 제한 | `adCounters`, `levelEndCount` |
| 사용자 | `settings`, `nickname`, `accountId` |

광고 일일 상한(`adCounters`)을 계정에 붙인 게 중요하다. 전역이나 세션에 두면 상한이 우회된다.

### guest → 계정 마이그레이션

로그인 전에 guest 로 플레이한 기록은 첫 로그인 때 계정 키로 옮긴다 (`migrateGuestSave`).
계정 저장이 이미 있으면 손대지 않는다 — 기존 계정 진행도가 우선이다.

### 서버 저장으로 옮기려면

localStorage 는 기기 단위라 기기를 바꾸면 진행도가 따라가지 않는다.
계정을 따라가게 하려면 `StorageAdapter` 를 하나 더 구현해 `setAdapter()` 로 갈아끼우면 된다
(Agent8 게임 서버의 `$global.getMyState()` / `updateMyState()` 가 그대로 대응된다).
게임 코드는 어댑터 종류를 알지 못하므로 이 파일 하나만 바꾸면 된다.
`SaveData.updatedAt` 이 있어 서버/로컬 병합 기준으로 쓸 수 있다.

## 언어 (`i18n.ts`)

한국어 · 영어 · 일본어 · 번체 중국어 넷. 설정에서 고르면 저장에 남는다(`settings.lang`).

사전은 **키 순서를 KO 와 똑같이** 유지한다. 빠진 키는 `t()` 가 한국어로 되돌려주므로
화면이 깨지지 않는데, 바로 그래서 **눈으로는 못 찾는다** — 영어 화면에 한국어가 한 줄
섞여 있어도 그냥 지나간다. `core.test.ts` 가 소스에서 키를 세어 세 가지를 고정한다:

- 네 사전의 키가 정확히 같은가 (누락도, 한쪽에만 있는 키도 실패)
- 번역문에 한글이 남아 있지 않은가 (일본어·번체는 한자를 쓰므로 이 검사에 안 걸린다)
- 치환 자리(`{n}`, `{t}`)가 원문과 같은가

언어 선택은 눌러서 돌리는 버튼이 아니라 **네 개를 늘어놓은 격자**다. 넷이면 원하는
언어까지 최대 세 번 눌러야 하고, 무엇이 있는지도 안 보인다. 좁은 화면(320px)에서
라벨이 잘리지 않게 2열로 접는다.

언어를 바꾼 뒤에는 이 모달만 다시 그려선 안 된다 — 지도·독·HUD 의 글자는 이미 그려져
있어서 그대로 남는다. 화면을 통째로 다시 그린 뒤 설정을 다시 연다.

## 모바일 대응

Verse8 은 모바일 앱(`io.verse8.mobile`) 웹뷰에서 게임을 띄운다. 세로 화면 기준으로 만들었다.

- `viewport-fit=cover` + `env(safe-area-inset-*)` — 노치·홈 인디케이터 회피 (가로 인셋 포함)
- `mobile-web-app-capable` / `apple-mobile-web-app-*` — 전체화면 실행
- `100dvh` (+ `100vh` 폴백), `position: fixed` body — 주소창 높이 변화·고무줄 스크롤 차단
- `touch-action: none` (보드) / `manipulation` (그 외) — 더블탭 확대, 스크롤 하이재킹 방지
- `-webkit-touch-callout: none`, `contextmenu` 차단 — 길게 눌러도 메뉴가 안 뜬다
- `PointerEvent` 미지원 구형 웹뷰용 `touchstart/touchend` 폴백
- 입력 시점에 캔버스 크기를 재확인 — `ResizeObserver` 가 밀려도 탭 좌표가 어긋나지 않는다
- iOS 오디오 언락 — 첫 터치에서 `AudioContext` 를 열어 타이머 효과음도 정상 재생
- 정지 화면에서는 캔버스를 다시 그리지 않는다 (배터리)
- devicePixelRatio 상한 2
- 가로 모드 / 360px 미만 좁은 화면 미디어 쿼리
- `navigator.vibrate` 미지원(iOS)은 조용히 무시
